<objective>
Split the done-phase container into its three natural widgets — the summary stat row, the two action buttons, and the goal-celebration modal — each with the test depth **D-01** assigns it by interactivity rather than by whether it holds local state.

**As a** student who just finished a session, **I want to** see the same completion summary, buttons, and celebration I saw before, **so that** the only thing that changed is the shape of the code behind them.

Purpose: the done branch is the smallest of the three, which makes it the right place to establish the two test tiers concretely — one genuinely pure-display component and two callback-only wrappers — before the same split is applied to the larger active and setup branches.

Output: three components under `components/FocusScreen/`, three test files, and a `FocusDoneScreen` that composes rather than inlines.

This expands out from plan 02-01's done-branch slice; it does not touch `mobile/src/screens/FocusScreen.jsx` at all, which is why it runs in parallel with plan 02-02.
</objective>
