<objective>
Split the first three option sections out of the setup container — subject, session length, and session goal — into named pickers with interaction tests that check the argument each handler receives, not just that it fired.

**As a** student choosing what and how long to study, **I want to** every chip, preset, and goal option to select exactly as before, **so that** the refactor is invisible from the outside.

Purpose: these three sections are where the screen's "filter-shaped" single-select behavior lives — the behavior FOCUS-01's stale wording was really pointing at. Isolating them makes that behavior testable per option set rather than only through the whole screen.

Output: three components under `components/FocusScreen/`, three test files, and a setup container that composes rather than inlines them.

This expands out from plan 02-04's container. Plan 02-07 takes the remaining four sections.
</objective>
