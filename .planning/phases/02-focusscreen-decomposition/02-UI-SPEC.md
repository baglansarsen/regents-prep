## Color

FocusScreen consumes color exclusively via `useTheme()` → `{ C }` (from `mobile/src/theme.js`,
`dark`/`light` token sets) plus one local `BACKGROUNDS` array (6 scene presets: sky/night/forest/
ocean/sunset/space, each with `top`/`bottom`/`accent` hex values) used only in the active-session
full-bleed background. No hardcoded hex values may be introduced during extraction beyond what
already exists in `BACKGROUNDS` and the few inline literals already in the file (e.g. `'#fff'`,
`'#1f2937'`, `'rgba(0,0,0,0.15)'` for header/control overlays on the active screen, `#000` shadow
colors).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `C.bg` (theme background) | Setup screen and Done screen full-bleed background (`s.safe`) |
| Secondary (30%) | `C.surface` / `C.surface2` | Chips, preset buttons, done-stat cards, custom-input rows, close buttons |
| Accent (10%) | `C.brand` (`#1FC36B` in both light/dark) | Active-state chips/presets/goal-chips, primary CTA (`startBtn`, `primaryBtn`), History link text, subject badge, goal-celebration button |
| Destructive | `style: 'destructive'` on the native `Alert.alert` "Stop & Save" button (system red, not a custom hex) | "End Session?" back-gesture guard and active-session Stop button confirmation |

Accent (`C.brand`) reserved for: primary CTA ("Start Focusing" button), selected/active chip and
preset states, the "History" text link, subject badge accent, and the goal-celebration modal's
"Keep Studying!" button. It is not used for body text, non-selected chips, or section labels.

Active-session screen additionally overrides text/muted colors per background scene (`textColor`/
`mutedColor` computed from `bg.id`, not theme tokens) — this is an existing exception where the
6 `BACKGROUNDS` presets supersede the light/dark theme while a session is active. Preserve this
override exactly; do not route it through `C.text`/`C.textMuted` during extraction.

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). Shape-rooted UI *state* coverage
> for FocusScreen's elements, evaluated against the CURRENT shipped behavior (this is a parity
> lock — "resolved" here means "the existing screen already handles this state, and extraction
> must preserve that handling," not that new handling is being designed).

Applicable state considerations resolved: 6 covered, 0 backstop, 2 unresolved (both pre-existing
gaps in the current screen, explicitly out of scope per FOCUS-01/06's "no behavior changes" — the
planner should NOT invent new empty/error handling this phase).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Tasks list (`todos`, list-collection) | ✅ covered | Zero todos renders as zero rows with no placeholder copy — the input row above it is always visible, so the section never looks visually broken; extraction must preserve rendering nothing rather than adding new empty-state copy |
| zero-one-many | Tasks list (`todos`, list-collection) | ✅ covered | 1 task and N tasks both render as a flat list of `todoRow`; no singular/plural copy differs (task text itself is user-authored) |
| zero-one-many | Session history (`history.length`, list-collection) | ✅ covered | Existing code already branches singular/plural: `"{n} past session" + (n > 1 ? 's' : '')`, and the History link is hidden entirely at `history.length === 0` |
| zero-one-many | Pomodoro count display (interactive-control/static-content) | ✅ covered | Existing ternary chain: hidden at 0 (no goal), `{count}/{goal} 🍅` when a goal is set, `🍅`.repeat when no goal — capped at 8 repeats to prevent overflow |
| overflow | Tasks list during active session (`activeTodos`, list-collection) | ✅ covered | `maxHeight: 160` + `ScrollView` already caps and scrolls; must preserve the 160 cap exactly |
| long-text | Custom subject / task input (`customInput`/`todoInputField`, form) | ✅ covered | Standard RN `TextInput`, single line, no explicit truncation — text simply scrolls within the field, which is the existing (acceptable) behavior |
| loading | Session state transitions (`phase`, interactive-control) | ⚠ unresolved | No loading/spinner state exists anywhere in FocusScreen (timer/session state is synchronous local state, not fetched) — correctly out of scope; flagged only so the planner doesn't assume one needs to be added |
| error | Session start/stop actions (`start`/`stop`/`skip`, interactive-control) | ⚠ unresolved | No error-state UI exists for session actions (they cannot fail in the current implementation — no network call) — correctly out of scope; flagged so extraction doesn't silently add error handling that changes behavior |
