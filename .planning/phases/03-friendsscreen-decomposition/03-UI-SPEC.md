# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Contract type: PARITY LOCK, not a redesign.** This phase extracts `FriendsScreen.jsx`
(`mobile/src/screens/FriendsScreen.jsx`, 987 lines) into `useFriendsScreenState` + named
sub-components under `mobile/src/components/FriendsScreen/`, with **no behavior or visual
changes** (FRIENDS-02, FRIENDS-03, FRIENDS-06). Every value below is transcribed from the current
shipped source, not proposed. The executor's job is pixel/behavior parity; any value it cannot
match exactly during extraction is a regression, not a judgment call. This mirrors Phase 2's
`02-UI-SPEC.md` (same format, same parity-lock approach, approved 2026-09-14). Source read:
`mobile/src/screens/FriendsScreen.jsx` (987 lines, read in full 2026-09-15),
`mobile/src/styles/duo.js`, `mobile/src/theme.js`.

**Assumption (structure-only refactor, no new CONTEXT.md/RESEARCH.md design questions to ask):**
all design-contract questions below are answered by reading the current implementation rather
than by asking the user — CONTEXT.md and RESEARCH.md for this phase already lock the
hook-composition, component-boundary, and animation-relocation decisions (D-01 through D-07);
this UI-SPEC only needed to transcribe the screen's existing visual/copy values, not gather new
decisions. Flagged as `[ASSUMED]` where a judgment call was still needed (e.g. categorizing
ad-hoc values against the 8-point grid).

## Color

FriendsScreen consumes color exclusively via `useTheme()` → `{ C }` (from `mobile/src/theme.js`,
`dark`/`light` token sets) plus `TIER_META`'s per-tier `color`/`emoji` values (from
`useLeague.js`, imported unchanged). No hardcoded hex values may be introduced during extraction
beyond what already exists inline in the file (medal palette in the module-local `MEDALS` array —
`#FCD34D`/`#94A3B8`/`#D97706` borders with matching text colors — and the `activityConfig` map's
per-activity-type accent colors: `#F59E0B` rp_earned, `#8B5CF6` level_up, `#3B82F6`
quiz_complete, `#06B6D4` exam_complete, `#F97316` speedround_complete, `#EF4444`
streak_extended/streak_milestone, `#10B981` focus_session_complete — plus the hardcoded `#fff`
white used on brand-colored button text/medal avatar borders and `#F59E0B` on `lbRP`/`podiumRP`
star-RP text).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `C.bg` (theme background) | Screen full-bleed background (`s.safe`) |
| Secondary (30%) | `C.surface` / `C.surface2` | Tab bar background, request/battle banners, leaderboard rows, friend cards, activity feed rows, code banner, mode-toggle background |
| Accent (10%) | `C.brand` (`#1FC36B` in both light/dark) | Active tab background, active mode-toggle segment, accept-request button, primary "Add"/"Play"/"Battle" pills, self-highlighted row border (`lbRowSelf`), self name-text color, friend-code value text |
| Destructive | Native `Alert.alert` "Remove" button with `style: 'destructive'` (system red, not a custom hex) | `confirmRemoveFriend`'s long-press-on-friend-card confirmation flow |

Accent (`C.brand`) reserved for: the active tab indicator, the active leaderboard-mode segment
("Friends"/"School"/"League" toggle), the accept-request checkmark button, "Add"/"Battle" action
buttons, the current-user's highlighted row border and name color across all three leaderboard
modes, and the friend-code display value. It is not used for body text, non-selected tabs/modes,
or section labels. Two additional semantic-ish colors are already in use beyond brand: `C.warn`
(streak badge background/border/text — `🔥 N day streak`) and `C.correct`/`C.wrong` (battle
outcome icon/text color — won/lost, distinct from the `Alert.alert` destructive-action red above).

## Visual Hierarchy (Per-Tab Focal Points)

Existing focal-point behavior per tab, transcribed from the current layout order and accent
usage — **describing what the shipped screen already does, not proposing new hierarchy.**
Extraction must preserve each tab's current first-glance order (component boundaries may change,
render order/emphasis must not).

| Tab | What draws the eye first (as currently rendered) |
|-----|----------------------------------------------------|
| LeaderboardTab | The Podium block (top-3, medal-colored avatars at 1/2/3 sizing) sits above the ranked list and renders first when `top3` is non-empty; within the podium and the rows below it, the current user's `lbRowSelf` border (`C.brand`) and name-color override are the next-strongest signal, distinguishing "you" from other ranked friends/classmates/league members |
| FriendsTab | The incoming friend-request banner (`"{fromName} wants to be friends"` with ✓/✕ buttons) renders above the friend list whenever a pending request exists, interrupting the normal card list — this is the strongest attention pull on the tab; when no request is pending, the friend-code banner (`"Your Friend Code"` + `codeValue`, `letterSpacing: 3`) and the "➕ Add" CTA are the first fixed elements above the scrolling `friendCard` list |
| BattlesTab | The "Your turn" section (pending incoming battle rows with a "Play" CTA) renders above the "Results" section whenever any battle is pending — action-required items are placed first; when no battle is pending, the empty-state block is the sole focal point |
| ActivityTab | Each `feedRow` leads with a colored icon (`feedIconWrap`, `activityConfig`'s per-type accent color: amber for RP, purple for level-up, blue for quiz, cyan for exam, orange for speedround, red for streak, green for focus) — the color-coded icon is the first-glance differentiator down the reverse-chronological feed, not the row text |
