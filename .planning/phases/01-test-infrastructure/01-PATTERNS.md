### `mobile/src/__tests__/rntlSmoke.test.js` (test, request-response) — NEW FILE

**Primary analog:** `mobile/src/__tests__/useQuiz.test.js` (full file read this session, 172 lines)
**Secondary analog (import/describe style):** `mobile/src/utils/__tests__/homeAgenda.test.js` (lines 1-15 read this session)

**File header / intent-comment pattern** (from `useQuiz.test.js` lines 1-14):
```javascript
/**
 * useQuiz logic tests
 *
 * useQuiz is pure React state — no Firebase, no AsyncStorage, no native modules.
 * Rather than fighting react-test-renderer version mismatches with Expo 52, we
 * test the pure functions that contain all the business logic directly.
 *
 * What's covered:
 *   - streakMultiplier thresholds
 *   - scoring: base points, multiplier application, rounding
 *   - wrong answer: 0 points, streak reset
 *   - bestStreak tracking
 *   - guard: calling answer() in non-answering phase is a no-op
 */
```
Apply the same convention for the new file: a top-of-file block comment stating this is a throwaway smoke test proving the RNTL v14 / `test-renderer` migration actually renders/hooks correctly (per RESEARCH.md Pattern 2), and that it is safe to delete once Phase 2 adds real `renderHook`/`render` tests for extracted hooks.

**Import style** (`homeAgenda.test.js` line 1 — plain relative import, no path alias, no barrel):
```javascript
import { buildHomeAgenda } from '../homeAgenda'
```
The smoke test's import is a package import instead of a relative one, following the same "flat, no-indirection" convention:
```javascript
import { renderHook } from '@testing-library/react-native'
import { useState } from 'react'
```

**Core pattern — flat `test()` calls, no `describe` wrapper needed for a single-assertion file** (`useQuiz.test.js` lines 39-42 style, generalized):
```javascript
test('multiplier is 1.0 for streak < 2', () => {
  expect(streakMultiplier(0)).toBe(1.0)
  expect(streakMultiplier(1)).toBe(1.0)
})
```
RESEARCH.md's Pattern 2 example applies this exact shape, but must `await` `renderHook` — the one behavioral difference from every existing test in this suite (RNTL v14 is async-by-default; no existing test awaits anything since none call RNTL):
```javascript
test('renderHook works under the new RNTL v14 / test-renderer setup', async () => {
  const { result } = await renderHook(() => useState(0))
  expect(result.current[0]).toBe(0)
})
```

**Error handling / validation pattern:** none needed — matches `useQuiz.test.js` and `homeAgenda.test.js`, both of which use plain `expect().toBe()`/`toEqual()` assertions with no try/catch. A thrown error inside `renderHook` fails the test naturally via Jest's own async-test-rejection handling; no custom error wrapping exists anywhere in this test suite to mirror.

**Testing convention — file location and naming:** lives in `mobile/src/__tests__/` (flat top-level test dir, not colocated with a `src/hooks/__tests__/`), matching `useQuiz.test.js`'s placement — both are cross-cutting/infra-proving tests rather than a single module's unit tests (which instead live in `mobile/src/utils/__tests__/` per `homeAgenda.test.js`, `achievements.test.js`, etc.). Filename `camelCase.test.js` matches the project's stated naming convention (see CLAUDE.md-adjacent AGENTS.md conventions: "Test files: camelCase with `.test.js` suffix").
