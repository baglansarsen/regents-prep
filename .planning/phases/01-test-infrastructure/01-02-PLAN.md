<objective>
Expand the proven tracer to RNTL v14's second entry point — `render()` — and prove that its built-in matchers replace the deprecated `@testing-library/jest-native` matchers with zero jest setup wiring.

**As a** developer about to decompose four screens into named sub-components, **I want to** know that `render()` and the built-in matchers work in this repo's test runner with no setup file, **so that** the render/snapshot test required for every extracted sub-component in Phases 2-5 (FOCUS-05, FRIENDS-05, QUIZ-06, HOME-05) rests on measured evidence.

Purpose: plan 01-01 removed `@testing-library/jest-native` and deleted the `setupFilesAfterEnv` key that wired its matchers in. That deletion rests on a documented claim — that RNTL v12.4+ ships those matchers built in and attaches them automatically on first import — which nothing in this repo currently exercises. Until a built-in matcher actually passes here, the config deletion is an untested assumption sitting under four phases of component tests.

Output: the smoke test grown from a renderHook proof into a full RNTL v14 reference file, covering both entry points and the matcher replacement.

**This is an expansion task on the tracer**, not a new slice: it widens the already-proven path rather than adding a layer beneath it. It runs in wave 2 because it edits the same file plan 01-01 creates.
</objective>
