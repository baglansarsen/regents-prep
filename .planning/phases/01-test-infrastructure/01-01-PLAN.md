<objective>
Prove, end-to-end, that `@testing-library/react-native@14.0.1` can render and drive a React hook inside this app's existing jest-expo / React 19.1.0 test setup — and make that the only rendering/query library in the manifest.

**As a** developer about to extract orchestration hooks out of four large screens, **I want to** know that `renderHook` genuinely works in this repo's test runner, **so that** the hook tests I write in Phases 2-5 are trustworthy evidence rather than assertions resting on a deprecated, React-19-incompatible renderer.

Purpose: `mobile/package.json` still pins `react-test-renderer@^18.3.1` (incompatible with the installed `react@19.1.0`) and the npm-registry-deprecated `@testing-library/jest-native@^5.4.3`. Phases 2-5 are entirely built on `renderHook`/`render`, so this foundation has to be verified, not assumed. Critically, **not one of the 23 existing test files imports `@testing-library/*` or calls `render`/`renderHook`** (verified by grep this session), which is why "the suite is green" proves nothing on its own here — the suite is green today, with the broken pins in place.

Output: a working `renderHook` smoke test committed alongside a manifest that carries RNTL 14.0.1 and nothing else for rendering.

**This is the tracer slice.** It wires one path through every layer this phase touches — install tree → devDependency manifest → jest config → a test file that actually exercises the rendering engine → a green `npm run check` — and it is production-quality, not a throwaway. Plan 01-02 expands out from it to the `render()` entry point and the built-in matchers.
</objective>
